# Handoff

## State (2026-11-06)

First complete build of Material Tailscale: Electron app, website, docs, release pipeline.

## Verification actually run

- `npm test`: 6 of 6 pass (catalogue integrity, argument validation, RFC 4226 HOTP vectors, RFC 6238 TOTP vectors for SHA-1, SHA-256 and SHA-512, admin catalogue coverage, settings explanations).
- Built app launched under Xvfb on Linux with Electron 37 and driven through 36 destinations in both themes; 73 PNGs in `docs/screenshots`. Tailscale was not installed there, so status-driven pages show the not-found state.
- The capture revealed and fixed two defects: untouched `set` flags were being sent, and `[hidden]` panes were visible.

- v1.0.11 · Classic Siu Mai · 燒賣 (commit a788bb7): 12 assets, notes pass the public-boundary scan, and the new install-proof job passed on a clean runner: v1.0.7 installed silently (NotSigned), updated to v1.0.11 with Update.exe (executable reports 1.0.11), uninstalled.

## Public-boundary sweep

- Every tracked text file passes the canonical public-boundary scan. This pass removed a personal nickname used as a sample tailnet name in a design board, private IPv4 example ranges (now RFC 5737 documentation ranges), and identifiers that matched governed words. The nickname remains in the design board's earlier commit (add934c); removing it from history needs a history rewrite, which is not done without the owner's explicit approval.

## Tooling added in the gap-closing pass

- `npm run record` produced `docs/recording/end-to-end.gif` (97 frames) from the built app under Xvfb.
- `npm run clip-matrix` checks cut-off text across scales, languages and the minimum window. The full matrix (100, 125, 150 and 200% in English, Cantonese and both, plus 960 by 640) now reports 0 clipped elements after fixing buttons shrinking in tight rows, a long timestamp, bilingual setting labels squeezed by tri-state controls, and duplicated bilingual labels such as "Tailnet · Tailnet".
- The release workflow now has an install-proof job: previous release installed silently on a clean runner, updated with Update.exe to the new release, checked, uninstalled, and the result appended to the release notes. Its first real run happens on the next push.
- `npm run gen:postman` writes a collection covering all 93 admin API operations; a test checks the count and that no token is stored.
- `npm run wiki` builds 55 wiki pages. Publishing is blocked from the build machine: the wiki repository could not be cloned with the available credentials (it may also need its first page created on GitHub).
- `npm run check:instructions` compares a SHA-256 of the maintainer's private instructions to `.instructions-lock`; it skips with a reason wherever those instructions are absent.

Capture mode now always sets the zoom (default 100%), and `docs/screenshots/capture-manifest.json` records the viewport, scale, zoom, motion and hash of each capture.

## Final polish pass

- Screens: Home without Tailscale and Minecraft without servers now show full-width first-run cards that match their boards (`home-setup`, the new `minecraft-setup` view). About is a hero with a working update check, a build table (version, code name, commit, source state, builder, runtime, installer) and a licences table. Status uses dot markers, folds the searched paths behind a count, and adds This device and Health when the daemon answers. The changelog lists every published release and shows unreleased work as unreleased.
- Bugs fixed:
  - About printed the text "null" when a build had no code-name photo (a native `append` of `null`).
  - Help requests copied from errors said "App version: unknown", because nothing set the version at boot.
  - The changelog read the heading "Unreleased: Midnight Mesh 2" as version 2, and could not read code names that contain " · ". The parser now lives in `scripts/lib/changelog.mjs` with tests.
  - Settings > Check for updates showed a raw status string; checks now report in the current language, and a copy without the Windows installer says it does not update itself.
- Release packaging: release runs 13 and 14 failed in "Package Squirrel.Windows installer". Each release had re-uploaded every earlier package, so Squirrel's GitHub sync downloaded the same file name from several releases at once and hit "The process cannot access the file ... because it is being used by another process", then fell back to a URL that returns 404. Packaging now seeds only the previous release's `RELEASES` and newest full package, builds one delta, and trims `RELEASES` to what the release ships.
- Canvas: version 10 publishes 15 boards and 49 views with the updated stylesheet.

## Blockers

- The build session could not inspect self-hosted runners (proxy refused the Actions API), so the workflow uses GitHub-hosted `windows-latest`.
- Wiki publishing: the wiki repository could not be cloned with the session's credentials. Run `npm run wiki -- --push` from a machine with access after creating the wiki's first page on GitHub.
- Live status registration for the build session was not possible: no ingest credential for the maintainer's status service was available to the session.
- A real Tailscale daemon was not run on the build machine; running a downloaded daemon needs the owner's permission.
